# Requirements Document

## Introduction

This document specifies requirements for adding two site sharing features to the main dashboard: a QR code generator for sharing the organization's site and a button to open the organization's site in a new browser tab. These features will enable users to quickly share and access their organization's public storefront from the dashboard interface.

## Glossary

- **Dashboard**: The administrative interface where users manage their organization
- **Organization_Site**: The public-facing storefront accessible via Site_URL
- **Site_URL**: The complete URL of the Organization_Site, determined by URL priority rules
- **Custom_Domain**: A user-owned domain name configured for the Organization_Site
- **Subdomain**: The default subdomain assigned to the organization (format: {subdomain}.tsuru.jcampos.dev)
- **Domain_Verification**: The process of proving ownership of a Custom_Domain via DNS TXT record
- **Verification_Token**: A unique string generated by the system for DNS-based domain verification
- **QR_Code_Generator**: A component that generates a QR code image encoding the Site_URL
- **QR_Code_Dialog**: A modal dialog that displays the generated QR code with sharing options
- **Open_Site_Button**: A button component that opens the Organization_Site in a new browser tab
- **Quick_Actions_Grid**: The existing dashboard component that displays action cards
- **Organization_Context**: The current organization data available in the dashboard, including subdomain, customDomain, and domainVerified fields
- **Domain_Settings_Page**: A settings page where users manage custom domain configuration

## Requirements

### Requirement 1: Determine Site URL Based on Domain Configuration

**User Story:** As a store owner, I want my site to use my custom domain when verified, so that my brand is consistent across all customer touchpoints

#### Acceptance Criteria

1. WHEN customDomain exists AND domainVerified is true, THE Dashboard SHALL construct Site_URL as https://{customDomain}
2. WHEN customDomain is null OR domainVerified is false, THE Dashboard SHALL construct Site_URL as https://{subdomain}.tsuru.jcampos.dev
3. WHEN both customDomain and subdomain are unavailable, THE Dashboard SHALL set Site_URL to null
4. THE Dashboard SHALL retrieve customDomain, domainVerified, and subdomain values from Organization_Context
5. WHEN Organization_Context updates, THE Dashboard SHALL recalculate Site_URL based on current domain configuration

### Requirement 2: Generate QR Code for Organization Site

**User Story:** As a store owner, I want to generate a QR code for my site, so that I can easily share it with customers in physical locations or printed materials

#### Acceptance Criteria

1. WHEN the user clicks the QR code action, THE QR_Code_Generator SHALL generate a QR code encoding the Site_URL
2. THE QR_Code_Generator SHALL use the Site_URL determined by domain configuration priority rules
3. WHEN Site_URL is null, THE QR_Code_Generator SHALL display an error message indicating the site is not available
4. THE QR_Code_Generator SHALL produce a scannable QR code that resolves to the Site_URL
5. THE QR_Code_Generator SHALL render the QR code with sufficient resolution for both screen display and printing

### Requirement 3: Display QR Code in Modal Dialog

**User Story:** As a store owner, I want to view the QR code in a clear dialog, so that I can see it clearly and access sharing options

#### Acceptance Criteria

1. WHEN the QR code is generated, THE QR_Code_Dialog SHALL display the QR code in a modal dialog
2. THE QR_Code_Dialog SHALL display the Site_URL as text below the QR code
3. THE QR_Code_Dialog SHALL provide a download button to save the QR code as an image file
4. WHEN the user clicks the download button, THE QR_Code_Dialog SHALL download the QR code as a PNG file with filename format "qr-code-{subdomain}.png"
5. THE QR_Code_Dialog SHALL provide a close button to dismiss the dialog
6. THE QR_Code_Dialog SHALL be responsive and display properly on mobile and desktop screens

### Requirement 4: Open Organization Site in New Tab

**User Story:** As a store owner, I want to open my site in a new tab, so that I can quickly preview my storefront while working in the dashboard

#### Acceptance Criteria

1. WHEN the user clicks the open site action, THE Open_Site_Button SHALL open the Site_URL in a new browser tab
2. THE Open_Site_Button SHALL use the Site_URL determined by domain configuration priority rules
3. WHEN Site_URL is null, THE Open_Site_Button SHALL be disabled
4. THE Open_Site_Button SHALL open the new tab with rel="noopener noreferrer" for security
5. WHEN Site_URL is null, THE Open_Site_Button SHALL display a tooltip explaining why it is disabled

### Requirement 5: Integrate Actions into Dashboard

**User Story:** As a store owner, I want to access site sharing features from the main dashboard, so that I can quickly share or view my site without navigating through menus

#### Acceptance Criteria

1. THE Dashboard SHALL display the QR code action in the Quick_Actions_Grid
2. THE Dashboard SHALL display the open site action in the Quick_Actions_Grid
3. THE Quick_Actions_Grid SHALL display appropriate icons for each action (QR code icon and external link icon)
4. THE Quick_Actions_Grid SHALL display descriptive labels for each action
5. WHEN the organization subdomain is available, THE Dashboard SHALL enable both actions
6. WHEN the organization subdomain is not available, THE Dashboard SHALL disable both actions and display appropriate visual feedback

### Requirement 6: Handle Missing Organization Context

**User Story:** As a developer, I want the features to handle missing organization data gracefully, so that the dashboard remains stable when organization context is unavailable

#### Acceptance Criteria

1. WHEN Organization_Context is null or undefined, THE Dashboard SHALL disable both site sharing actions
2. WHEN the subdomain property is missing from Organization_Context, THE Dashboard SHALL disable both site sharing actions
3. IF Organization_Context becomes available after initial render, THEN THE Dashboard SHALL enable the site sharing actions
4. THE Dashboard SHALL not throw errors when Organization_Context is unavailable
5. WHEN actions are disabled due to missing context, THE Dashboard SHALL provide clear visual indication that the features are unavailable

### Requirement 7: Add Custom Domain to Organization

**User Story:** As a store owner, I want to add my custom domain to my organization, so that my site can be accessed via my own branded domain

#### Acceptance Criteria

1. THE Domain_Settings_Page SHALL provide an input field for entering a Custom_Domain
2. WHEN the user submits a Custom_Domain, THE Domain_Settings_Page SHALL validate the domain format
3. WHEN the domain format is invalid, THE Domain_Settings_Page SHALL display an error message describing the validation failure
4. WHEN the domain format is valid, THE Domain_Settings_Page SHALL send a request to save the Custom_Domain to the organization
5. WHEN the Custom_Domain is saved successfully, THE Domain_Settings_Page SHALL display the domain verification instructions
6. THE Domain_Settings_Page SHALL set domainVerified to false when a new Custom_Domain is added

### Requirement 8: Generate Domain Verification Token

**User Story:** As a store owner, I want to receive a verification token, so that I can prove ownership of my custom domain

#### Acceptance Criteria

1. WHEN a Custom_Domain is added to an organization, THE System SHALL generate a unique Verification_Token
2. THE Verification_Token SHALL be a cryptographically secure random string of at least 32 characters
3. THE System SHALL store the Verification_Token associated with the organization
4. THE System SHALL display the Verification_Token to the user in the Domain_Settings_Page
5. THE Verification_Token SHALL remain constant until the Custom_Domain is changed or removed

### Requirement 9: Display DNS Verification Instructions

**User Story:** As a store owner, I want clear instructions for DNS verification, so that I can configure my domain correctly

#### Acceptance Criteria

1. WHEN a Custom_Domain is added, THE Domain_Settings_Page SHALL display DNS TXT record instructions
2. THE Domain_Settings_Page SHALL display the TXT record name as "_tsuru-verification"
3. THE Domain_Settings_Page SHALL display the TXT record value as the Verification_Token
4. THE Domain_Settings_Page SHALL provide a copy button to copy the Verification_Token to clipboard
5. THE Domain_Settings_Page SHALL display the expected DNS record format: "_tsuru-verification.{customDomain} TXT {verificationToken}"
6. THE Domain_Settings_Page SHALL provide a link to common DNS provider documentation

### Requirement 10: Verify Custom Domain Ownership

**User Story:** As a store owner, I want to verify my domain ownership, so that my custom domain can be activated for my site

#### Acceptance Criteria

1. THE Domain_Settings_Page SHALL provide a "Verify Domain" button
2. WHEN the user clicks "Verify Domain", THE System SHALL perform a DNS TXT record lookup for "_tsuru-verification.{customDomain}"
3. WHEN the DNS TXT record value matches the Verification_Token, THE System SHALL set domainVerified to true
4. WHEN the DNS TXT record is not found OR the value does not match, THE System SHALL display an error message with troubleshooting guidance
5. WHEN domainVerified is set to true, THE Domain_Settings_Page SHALL display a success message indicating the domain is verified
6. WHEN domainVerified is true, THE Domain_Settings_Page SHALL display the verification status with a visual indicator

### Requirement 11: Display Domain Verification Status

**User Story:** As a store owner, I want to see my domain verification status, so that I know whether my custom domain is active

#### Acceptance Criteria

1. WHEN a Custom_Domain exists, THE Domain_Settings_Page SHALL display the current verification status
2. WHEN domainVerified is true, THE Domain_Settings_Page SHALL display a "Verified" badge with a success indicator
3. WHEN domainVerified is false, THE Domain_Settings_Page SHALL display a "Not Verified" badge with a warning indicator
4. WHEN domainVerified is false, THE Domain_Settings_Page SHALL display the verification instructions
5. WHEN domainVerified is true, THE Domain_Settings_Page SHALL hide the verification instructions

### Requirement 12: Remove or Update Custom Domain

**User Story:** As a store owner, I want to remove or change my custom domain, so that I can update my site configuration as needed

#### Acceptance Criteria

1. THE Domain_Settings_Page SHALL provide a "Remove Domain" button when a Custom_Domain exists
2. WHEN the user clicks "Remove Domain", THE Domain_Settings_Page SHALL display a confirmation dialog
3. WHEN the user confirms removal, THE System SHALL set customDomain to null and domainVerified to false
4. WHEN the Custom_Domain is removed, THE Dashboard SHALL revert to using the Subdomain for Site_URL
5. THE Domain_Settings_Page SHALL allow updating the Custom_Domain by entering a new domain value
6. WHEN a Custom_Domain is updated, THE System SHALL set domainVerified to false and generate a new Verification_Token

### Requirement 13: Handle DNS Verification Errors

**User Story:** As a developer, I want DNS verification errors to be handled gracefully, so that users receive helpful feedback when verification fails

#### Acceptance Criteria

1. IF DNS lookup fails due to network error, THEN THE System SHALL display an error message instructing the user to retry
2. IF DNS TXT record is not found, THEN THE System SHALL display an error message with instructions to add the TXT record
3. IF DNS TXT record value does not match, THEN THE System SHALL display an error message showing the expected and actual values
4. IF DNS lookup times out, THEN THE System SHALL display an error message indicating DNS propagation may be in progress
5. THE System SHALL log all DNS verification errors for debugging purposes
